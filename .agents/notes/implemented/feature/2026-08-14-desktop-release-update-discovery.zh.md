# Agent Note: Desktop 发布更新发现

Status: implemented

[English](2026-08-14-desktop-release-update-discovery.md) | 中文

## 问题

[Desktop 分发](../architecture/2026-08-14-electron-desktop-shell-and-distribution.md)已提供可安装产物，但已安装应用无法判断自身版本与仓库当前版本的关系。用户只能重新访问 GitHub 并手动比较文件名。尚未签名的安装包还不能安全支持无人值守替换，但这一限制不应妨碍应用可靠发现新版，也不应妨碍用户明确进入正确的下载页面。

## 决策

**由 Electron 主进程持有发布发现。**正常应用窗口启动后，以及用户选择**帮助 → 检查更新…**时，主进程都会请求本仓库固定且无需认证的 GitHub Latest Release endpoint。renderer 不会获得 bridge、API、token 或额外导航权限。

**只有有效 Desktop Release 才参与比较。**响应必须携带 `desktop-v<version>` tag，且后缀必须是有效 SemVer。应用使用标准 `semver` 包将其与 `app.getVersion()` 比较，其中包含稳定版与预发布版之间的优先级。请求上限为 8 秒。无效本地版本、非成功 HTTP 响应、格式错误的 JSON、无效 tag、超时与网络失败都会转为非致命的 unavailable 结果。

**自动检查与手动检查采用不同展示规则。**启动检查只在存在较新 Release 时显示原生对话框。手动检查还会报告已是最新版本和暂时无法检查两种结果。原生菜单保留 Electron 的标准应用、文件、编辑、视图与窗口 role，并为中文应用 locale 提供本地化的更新操作与对话框。

**发现新版不会安装软件。**选择**下载更新**或**查看发布页面**只会通过操作系统浏览器打开固定 HTTPS 发布页面。Desktop 不接受 API 响应中的下载 URL，不下载可执行文件，不提升权限，也不替换自身文件。所有支持平台的安装包完成签名且 macOS 产物完成公证前，不启用无人值守安装。

## 曾考虑的替代方案

**立即采用 `electron-updater`。**不采用：下载或替换未签名二进制文件，会在 Gatekeeper、SmartScreen、完整性和发布者身份警告仍然存在时提供误导性的一键体验。发布发现可以带来实际价值，同时不会声称安装过程已受信任或可以无人值守完成。

**把检查器放入 Web renderer。**不采用：更新发现属于已安装的应用壳，不属于共用 Web 应用。在 renderer 中实现会增加跨源网络行为，还需要仅为打开原生下载流程而新增主进程 bridge。

**每次启动都自动打开 GitHub。**不采用：已是最新版本或出现临时网络故障时，都不应打断启动。只有用户明确选择菜单操作，或接受新版提示时，才会打开浏览器。

## 后果

已安装的 Desktop 应用无需凭据即可识别公开可见的较新 Release，并把用户带到仓库支持的安装包。GitHub 故障或响应格式错误只影响更新状态，不会影响应用启动。每次正常启动会向 GitHub 发送一次有上限的公开 API 请求，手动检查也会发起请求。在签名与公证足以支持另一套自动更新设计之前，安装仍由用户通过操作系统明确执行。

## 模型体验

更新检查器完全在 Electron 壳中运行。它不会添加模型请求内容、工具、提供方行为、session 事件或 transcript 输出。

#### KV Cache 影响

无。更新发现不会进入模型上下文。
